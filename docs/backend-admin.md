# 动态站管理控制台

本功能只维护在 `dynamic-site`。`main` 和 `static-site` 的源码、依赖、构建及部署流程不变；不要把这次后端提交 cherry-pick 到静态分支。

## 当前部署

2026-09-08 已将新版后台启用到正式服务器，并验证公网登录、五个后台页面、访客记录及文章保护。

| 项目 | 当前配置 |
| --- | --- |
| 正式入口 | [https://lyrazeta.space/admin](https://lyrazeta.space/admin) |
| 后端服务 | 系统级 `lyrazeta-backend.service` |
| 内部监听 | `127.0.0.1:4000`，由 Nginx 提供公网 HTTPS |
| 环境配置 | `server/.env`，沿用原管理员账号和密码 |
| 文章保护 | `server/data/protected_posts.yml`，保留原配置 |
| 访问和审计数据 | `server/data/activity.sqlite3`，使用正式数据目录 |
| 临时预览 | 原 4001 预览服务已关闭，测试数据库未导入正式站 |

`127.0.0.1` 始终指访问者自己的机器。从个人电脑打开服务器后台应使用正式域名，本机端口仅供服务器内部检查。新访客日志从新版正式服务启动后开始记录，不包含旧 Nginx 日志。

本次启用复用了线上已有的 Nginx 代理；仓库模板中的独立 `/admin` 代理规则尚未替换到系统配置。线上后台资源当前通过静态资源规则的后端回退正常提供。后续重新配置时按 [Nginx 部署说明](deployment/nginx-reverse-proxy.md) 应用模板。

## 登录账号维护

后台使用 `server/.env` 中的 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD`。模板默认用户名是 `admin`，正式站以私有配置为准；没有通用默认密码。实际密码不写入 README、配置示例、截图或 GitHub。

管理员可在服务器终端查看或编辑私有配置：

```bash
nano server/.env
```

如需改密，仅修改 `ADMIN_PASSWORD`，保留 `APP_SECRET` 及其他配置，随后执行：

```bash
chmod 600 server/.env
sudo systemctl restart lyrazeta-backend.service
```

重启后旧后台会话失效，使用新密码重新登录。管理员登录密码与每篇文章的访问密码相互独立；修改管理员密码不会修改文章密码。不要使用 `.env.example` 覆盖已有的 `server/.env`。

## 外观设置

登录页和后台右上角提供三个图标选项：显示器为跟随系统，太阳为日间模式，月亮为夜间模式。首次访问默认跟随系统；也可以使用键盘切换选项。

选择保存在当前浏览器的 `lyra-admin-theme` 设置中，刷新、切换后台页面和重新登录后继续生效，并同步到同一浏览器已打开的后台标签页。选择跟随系统时，操作系统主题变化会立即反映到后台。浏览器禁止本地存储时仍可切换，但不会在刷新后保存手动选择。

后台主题独立于博客前台的日夜设置，也不改变 GitHub Pages 静态站。日夜模式覆盖登录、概览、图表、文章管理、访问日志、审计和设置；样式使用统一颜色变量，保持文字和操作状态的对比度。后台仍不添加动画或自动轮询。

## 启动与升级

```bash
bundle install
bin/build-dynamic
ADMIN_PASSWORD=你的强密码 bundle exec ruby server/app.rb
```

上述命令用于本机调试，访问 `http://127.0.0.1:4000/admin`。已有正式服务占用 4000 时，调试进程需另选端口及独立 `DATA_DIR`。没有管理员密码时后台返回 503。`server/.env` 是 systemd 的环境文件，直接在终端运行时需显式传入环境变量。

已使用 systemd 的服务器在安装依赖后执行：

```bash
sudo systemctl restart lyrazeta-backend
curl --fail http://127.0.0.1:4000/api/health
```

生产入口为 `https://lyrazeta.space/admin`。后台资源直接由 Ruby 服务，不进入 `_site`。文章页面、首页列表和 RSS 必须经过 Ruby，否则文章保护、摘要过滤和访问统计可能被绕过。

升级后重新登录后台。已有 `protected_posts.yml` 保留；文章解锁凭证现在与当前密码哈希绑定，更新密码后旧凭证失效，升级前的凭证也需要重新获取。

动态后端还会去掉首页及分页列表中的受保护摘要、从 RSS 中剔除受保护文章，并清除公开 API 中对应的摘要、描述和源文件路径。列表和订阅不缓存，Range 和条件请求也经过过滤；不会修改磁盘上的 Jekyll 产物。保护配置损坏时请求失败，不自动退回全部公开。

## 页面与操作

| 页面 | 功能 |
| --- | --- |
| `/admin` | 最近 7 / 30 / 90 天请求量、独立 IP、失败请求、文章保护数、每日趋势、热门路径和最近访问 |
| `/admin/posts` | 标签集合总览，集合内搜索、保护状态筛选及分页，设置或更新访问密码，取消保护 |
| `/admin/visits` | IP、路径、日期范围、响应状态和疑似爬虫筛选；IP 下方展示白名单备注；分页；展开来源和 User-Agent |
| `/admin/visits.csv` | 按当前筛选条件导出最近至多 10,000 条记录，UTF-8 BOM，已防止 CSV 公式注入 |
| `/admin/audit` | 成功及失败登录、退出、文章保护变更、日志设置、导出和清空操作 |
| `/admin/settings` | 访客 IP 白名单管理，启停访问采集、调整日志保留天数、输入 DELETE 确认清空访问日志 |

数据界面使用 UTC+08:00；CSV 时间为 UTC。独立 IP 不等于实际人数，同一网络可能共用一个 IP，同一人也可能更换 IP。疑似爬虫基于 User-Agent 判断，不代表可靠的身份识别。

### 文章标签集合

文章管理首页按 Markdown front matter 中的 `tags`（兼容 `tag`）展示集合，不再混排全部文章。每个集合显示文章数、公开和已保护数量，以及最新发布的文章；集合按匹配文章数量从多到少排列，同数量按标签名称排序，「未标记」置于最后。

点击集合进入该标签的文章列表，按发布日期倒序，每页最多 30 篇。多标签文章出现在每个对应集合，同一集合内不会因重复标签重复计数；总览文章总数按文章去重，可能小于各集合数量之和。没有标签的文章归入「未标记」，与名称恰好为「未标记」的真实标签独立。

总览的搜索和访问状态筛选同步更新集合及数量；集合内的筛选仅作用于当前标签，重置筛选不会退出集合。通过「标签集合」返回总览；分页、关闭密码编辑、保存密码或取消保护均保留标签和筛选范围。收藏链接可使用 `/admin/posts?tag=Course`，未标记集合为 `/admin/posts?untagged=1`。

标签沿用文章源文件，不会在后台自动改写或重新分类源文件。修改源文件的标签后刷新后台即可读取，前台页面仍按原 Jekyll 构建流程更新。本功能只影响动态后台，不修改博客前台和静态分支。

## 访客 IP 白名单

入口：[设置 → 访客 IP 白名单](https://lyrazeta.space/admin/settings#ip-allowlist)。填写单个 IPv4 或 IPv6 地址，可附最多 120 字的备注；点击「加入白名单」保存。列表中的删除图标用于移除地址，需确认操作。可从访问日志查找访客实际使用的地址，不要把代理配置 `TRUSTED_PROXIES` 当成访客白名单。

默认名单为空，不会自动加入管理员、服务器或当前访客 IP。不支持网段（CIDR）、通配符、域名、端口或带接口标识的 IPv6；IPv6 会规范化保存，IPv4 映射地址与对应 IPv4 视为同一地址，重复添加不会覆盖原备注。

访问日志的「访客 IP」下方显示该地址当前的白名单备注，IPv4 映射地址、IPv6 不同等价写法会规范化匹配。未填写备注或不在名单中时不显示备注行；移除后再加入新的备注，刷新日志即可更新历史记录的展示，不改写历史日志。此标注不表示该次历史访问当时已通过白名单授权；CSV 导出仍保持原有字段，不附加备注。

名单中的访客无需文章密码即可访问全部受保护文章，普通文章地址与 `/index.html` 别名均适用。名单逐请求检查，添加和移除立即生效，无需重启；白名单放行不会签发长期解锁 Cookie。移除后，仅凭白名单获得访问权的访客再次请求文章时需输入密码；原先通过密码解锁的有效 Cookie 仍遵循原有规则。已经阅读、下载的内容无法撤回。

白名单不等于管理员账号，不允许访问后台、访客日志或导出接口。首页摘要、RSS 和公开 API 继续过滤受保护内容，不因白名单增加公开输出；受保护页面及解锁跳转禁止缓存。已有文章密码和保护状态不变，名单之外的访客仍需密码。

只信任 TCP 客户端或配置的可信代理链中识别出的实际访客，不信任任意 `Client-IP` / `X-Real-IP` 或转发链最左侧的自报地址。经过可信代理时，缺少、超长、格式错误或仅包含可信代理的转发链都不用于白名单授权，即使代理自身地址在名单中也不会因此放行。日志可能仍回退记录代理地址，这不代表该地址可用于免密访问。

**授权风险：IP 不是个人身份。** 家庭、公司、校园、移动网络或 VPN 可能多人共用同一个公网 IP，加入该地址会让这些人都能阅读全部文章。动态 IP 和 IPv6 隐私地址可能变化或重新分配，应及时移除不再使用的地址；涉及敏感内容时优先使用文章密码。

名单保存在私有数据库 `activity.sqlite3` 的 `ip_allowlist` 表，随数据库备份，不写入 GitHub。首次升级重启时自动新增空表，保留原日志和配置。清空日志、暂停采集和日志到期清理不会删除名单；添加和移除操作记录在操作审计中。当前权限随整个数据库持久化，恢复较旧的数据库备份也会恢复当时的白名单，恢复后应复核授权。

## 采集范围与存储

只采集页面 GET 请求，包含正常页面、保护密码页、重定向和 404 等最终状态；不采集 HEAD、图片、CSS、JS、后台、API 和解锁表单请求。页面请求数不是成功阅读次数，耗时包含后端响应发送时间。

每条记录包含时间、IP、页面路径、HTTP 状态、耗时、来源地址和 User-Agent。路径不含查询参数；来源去掉账号、密码、查询参数和 fragment；不保存请求体、Cookie 或 Authorization。各文本字段有长度限制，HTML 输出转义。

访问日志、操作审计和设置保存在 `server/data/activity.sqlite3`。数据库使用 WAL、索引和分页查询，文件权限为 `0600`。`*.sqlite3*` 及文章保护文件已加入 `.gitignore`，`server/` 已被 Jekyll 排除。`DATA_DIR` 可指定独立的私有数据目录，不可位于 `STATIC_ROOT` 内。不要把该目录配置为 Nginx 静态目录。

默认保留 30 天，可设置 1 到 365 天。启动和修改保留策略时立即清理；有请求或后台查询时每小时检查一次。暂停采集不停止审计，清空访问记录不删除操作审计。较短的保留期会立即删除超期数据。已有 Nginx / systemd 日志不在此清理范围内；SQLite 删除后的空闲页会复用，不承诺数据库文件立刻缩小。

备份时停服务后复制整个数据目录，或使用 SQLite backup API 进行在线备份。WAL 模式下不要只复制正在使用的主数据库文件。

## 可信代理与登录

`TRUSTED_PROXIES` 默认仅信任 `127.0.0.1/32,::1/128`。直连客户端使用 TCP 对端 IP，忽略其转发头。经过可信代理时，从 `X-Forwarded-For` 的右侧逐跳剔除可信代理，取第一个不可信节点作为客户端。错误的 IP 或过长的转发链回退到 TCP 对端。

如增加容器代理或 CDN，应只加入实际代理的地址或网段，并同步配置代理追加或覆盖转发头；不要设置 `0.0.0.0/0`。`X-Real-IP` 和 `Client-IP` 不用于统计。后端仅监听 HTTP，TLS 由可信 Nginx 终止；只有来自可信代理的 `X-Forwarded-Proto: https` 才开启 Secure Cookie。

管理员会话为随机令牌，仅在服务进程内保存其 SHA-256 摘要，服务端有效期 12 小时。退出会立即撤销会话，重启会使全部后台会话失效。Cookie 使用 HttpOnly、SameSite=Strict；后台禁止缓存和 iframe 嵌入，修改操作校验 CSRF。每 IP 在 15 分钟内连续失败 5 次后限流，重启会清空限流计数。当前适用于一个后端进程，多实例部署前需共享会话和限流存储。

后台日志不公开，只有登录的管理员可查看和导出。动态站密码保护不改变 GitHub Pages、公开仓库、历史缓存或已公开图片的可访问性。

## 访问故障排查

从个人电脑使用正式域名，避免访问 `127.0.0.1:4000` 或已关闭的 4001 预览端口。在服务器终端检查：

```bash
systemctl status lyrazeta-backend.service
curl --fail http://127.0.0.1:4000/api/health
curl --fail --location --output /dev/null --write-out '%{http_code}\n' https://lyrazeta.space/admin
journalctl -u lyrazeta-backend.service -n 50 --no-pager
```

未登录访问 `/admin` 返回 303 跳转，最终登录页应为 200。502 通常表示代理无法连接后端；503 表示后台账号未配置。登录显示 429 时需等待 15 分钟再试；表单返回 403 时重新打开登录页或刷新当前后台页面获取新的 CSRF 令牌。

若旧版在输入正确文章密码后停留在 `/unlock`，并显示 `URI must be ascii only`，原因是中文文章路径未编码就被传入重定向。已修复为先对路径做 UTF-8 百分号编码，再返回 303 跳转；解锁凭证仍使用原规范路径，不需要重新设置文章密码。更新后重启后端服务，并用未解锁的浏览器会话验证提交密码后直接进入正文。
